1. **真实代码双端编译运行**：在临时隔离目录 `/tmp/bodyseek_replay_v1_v2` 中，分别编译：

   - `SleepAnalysis` 按 `Watch > AutoSleep > iPhone` 优先级去重时间重叠片段后汇总 `asleep / deep / rem / core / awake / inBed` 与入睡/醒来时刻；

   - 步数按 Watch 主源优先防双计。

## 三、分指标最大偏差日样本与根因分析

### 1. 恢复（Recovery）
- **最大差异特征**：v2 均值比 v1 高 `+16.38`，且覆盖天数多出 `547` 天（`v2_only = 547, v1_only = 0`）。
- **代表性偏差日**：
  - `2026-02-23`：v1=`34.2`, v2=`79` (`+44.8`) — `HRV 52.28ms, RHR 63.0bpm, 睡眠 32m`
  - `2026-07-06`：v1=`41.4`, v2=`83` (`+41.6`) — `HRV 60.84ms, RHR 62.0bpm, 睡眠 184m`
  - `2026-01-17`：v1=`44.2`, v2=`85` (`+40.8`) — `HRV 62.39ms, RHR 58.5bpm, 睡眠 163m`
  - `2023-07-27`：v1=`26.3`, v2=`66` (`+39.7`) — `HRV 43.74ms, RHR 57.0bpm, 睡眠 161m`
  - `2026-02-09`：v1=`46.8`, v2=`85` (`+38.2`) — `HRV 54.84ms, RHR 59.0bpm, 睡眠 679m`
- **根因**：
  1. **中位锚点不同**：v1 以 Sigmoid `50` 作为基线中位锚点，v2 以 `68` 作为基线锚点（直接带来约 `+16` 分结构性偏移）；
  2. **缺失睡眠门控**：v1 严格要求“前夜睡眠 + 至少一项心血管指标”，导致仅有日间/晚间手表 HRV+RHR 而无睡眠分期的 547 天输出 `nil`，v2 则按可用权重重新归一化；
  3. **短睡眠惩罚**：当睡前仅有 32 分钟片段时，v1 睡眠分接近 0 且占 25% 权重；v2 将 `durationScore` 钳位在 `>=20` 且睡眠权重为 18%。

### 2. 睡眠（Sleep）
- **覆盖一致**：`v1 = v2 = 670` 天（门槛相同：有效睡眠时长 `> 0`）。
- **代表性偏差日**：
  - `2026-01-26`：v1=`6.3`, v2=`84` (`+77.7`) — `sleep=772m` (~12.9h)
  - `2026-01-25`：v1=`11.6`, v2=`86` (`+74.5`) — `sleep=773m`
  - `2026-02-09`：v1=`15.1`, v2=`85` (`+69.9`) — `sleep=679m`
  - `2026-04-15`：v1=`18.4`, v2=`83` (`+64.7`) — `sleep=762m`
  - `2026-04-22`：v1=`24.5`, v2=`89` (`+64.5`) — `sleep=696m`
- **根因**：v1 `SleepScoreEngine` 在超过 `target + 60m`（510m）后实施强倒 U 型线性扣分，到 `+240m`（750m）时时长分衰减为 0；而 `score-v2` 将 `durationRatio` 钳位在 `1.08` 封顶，并纳入了 `25%` 的深睡/REM 修复期比例（v1 主要权重在时长 + 入睡一致性）。*工程启示：M1 `sleepMergePolicy` 应将午睡与主夜间睡眠显式分离，防止总睡眠小时数包含白天午睡而虚高。*

### 3. 负荷（Strain）
- **覆盖一致**：`v1 = v2 = 1508` 天，相关性 `r = 0.6568`。
- **代表性偏差日**：
  - `2022-10-15`：v1=`82.1`, v2=`12` (`-70.1`) — `kcal=99.86, ex=0m, steps=3108, w=0`
  - `2023-01-23`：v1=`86.8`, v2=`21` (`-65.8`) — `kcal=179.97, ex=0m, steps=6560, w=0`
  - `2023-01-22`：v1=`89.2`, v2=`25` (`-64.2`) — `kcal=215.58, ex=0m, steps=7400+`
  - `2023-07-22`：v1=`100.0`, v2=`36` (`-64.0`) — `kcal=304.40, ex=0m, steps=12322, w=1`
  - `2023-02-02`：v1=`98.1`, v2=`35` (`-63.1`) — `kcal=298.87, ex=0m, w=1`
- **根因**：2022–2023 初只有 iPhone 步数与低活动消耗、无 Watch 心率历史时，v1 的日常活动负荷相对于极低近期中位负荷迅速推高 `loadRatio > 2`，通过 `100*(1-exp(-0.75*ratio))` 输出高达 `82–100` 的虚高 Strain；`score-v2` 设立 `baselineKcal >= 320` 保底基准线并联合锻炼时长，有效避免了轻活动日虚高。同时观察到 `score-v2` 的最大分封顶在 `93`（`85 * 0.68 + 35 = 92.8`），已在模型卡中如实说明。

### 4. 压力（Stress）
- **覆盖差异**：`v1_only = 267`, `v2_only = 186`, 重合 `1,040` 天，均值几乎无偏（Bias `+0.46`）。
- **代表性偏差日**：
  - `2024-05-03`：v1=`95.0`, v2=`38` (`-57.0`) — `HRV/RHR=nil, kcal=713.7, ex=54m, w=5`（5 次锻炼且 12:00 前后处于/邻近训练窗）
  - `2025-07-01`：v1=`33.1`, v2=`71` (`+37.9`) — `HRV=48.86, RHR=55, kcal=1130.9, ex=133m`（v1 中 10% 负荷分权重；v2 将负荷分直接纳入三项均值且权重提升至 1/3）
- **根因**：v1 在 2022–2023 初缺少 HRV/RHR 时仍允许仅凭睡眠债务或负荷输出压力（`267` 天，如 `2022-10-03` 无任何心率样本却给 `98.1`）；`score-v2` 严格要求至少有一项心率/HRV 信号才发布 Stress，杜绝了无心血管样本时的压力估计；而 2023 年 5–7 月有全天心率样本时 `v2` 利用 `daytimeMeanHeartRateBpm` 覆盖了 `186` 天。M1-UI 与 M1-Data 需把旧 v1 中的“运动后 90 分钟恢复窗口排除态”通过 `excluded` 四态显式恢复到日内压力柱。

### 5. 能量（Energy）
- **总体偏差最小**：`Bias = -0.23`，`<=10 pts` 占比 `54.9%`（五项最高），相关性 `r = 0.6558`。
- **代表性偏差日**：
  - `2026-01-25`：v1=`22.0`, v2=`64` (`+42.0`) — 上游 `v1 Sleep` 因超长睡眠扣分坍塌至 `11.6` 所致；
  - `2023-09-21`：v1=`48.8`, v2=`14` (`-34.8`) — 当日 `kcal=881.4, w=3`，v1 在评估时点命中运动后 90 分钟排除窗口未扣除压力扣减，而 v2 未排除当日 `Stress=76`，叠加高负荷扣减后降至 `14`。

## 四、对后续 M1–M4 的直接工程结论

1. **`score-v2`（`BevelScoringEngine`）正式确立为当前基线版本**：中位与分布稳定、避免了无心血管样本虚高 Strain/Stress 以及超长睡眠坍塌等问题，并已在 `BevelScoringEngine` 中固定为 `AlgorithmVersion.scoreV2`（输出附 `contributors` 与 `DayKey`）。
2. **明确需要进 M1/M4 改进清单的三个真实信号与策略问题**：
   - M1 睡眠切分合并必须实现“夜间主睡眠 vs 白天午睡”分离与确定性多源去重；
   - M1 日内压力需重新接入运动后 90 分钟 `excluded(.postWorkoutWindow)` 状态；
   - `BevelScoringEngine` 在 `score-v2` 保持向后兼容，任何权重调整（如解除 Strain `93` 分天花板或接入腕温/`PhysicalEffort`）必须作为独立版本 `score-v3` 并另附回放对比报告。
