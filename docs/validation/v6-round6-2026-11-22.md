## 1. 今日页

- 结构：`BSPage` 按 L0–L3 排布。L0 是 `BSScoreRing.group`（恢复为大环，睡眠、负荷、压力、能量为中环）；L1 是 `BSCoachNote`，内容来自 `DailyBrief.headline`，`BriefFeedbackBar` 放在它下面；L2 依次是"今天要不要行动"、"昨夜睡眠"（`BSChartCard` + `SleepStageChart`）、"关键体征"（`BSMetricGrid`）、"今日训练与营养"（各一行摘要，点击跳转）。
- 组件扩展：`BSScoreRing` / `BSScoreItem` 增加 `identifier`、zoom 转场来源（`BSZoomSource`）；`BSActionRow` 增加次要按钮（跳过）和三个标识；`BSStateView`、`BSCoachNote` 增加按钮标识。
- 新增 `TodayFeature.Action.openWorkoutTapped`（转成已有的 `openWorkoutInbox` delegate）。
- 删除或合并的模块（对照削减清单）：
  | 原模块 | 处置 |
  | :--- | :--- |
  | `healthOverviewCard` + `stressAndEnergyRow` | 合并为 L0 `BSScoreRing.group`；压力、能量的日内小图不再出现在首屏 |
  | `todayQuickVerdictBanner` | 删除；`today-quick-verdict` 标识转给 L1 的 `BSCoachNote` |
  | `todayActionCard` + `aiSuggestion` | 合并为 L2①，用 `BSActionRow`（最多 3 条，计划条目优先，没有时退回简报里的行动）；"AI 参考依据"折叠区删除 |
  | `proactiveInsightsSection` | 删除（并入简报的 `changes`；reducer 里的 `proactiveInsights` 状态保留，页面不再读取） |
  | `sleepCard`、`vitalsGrid` | 换成 `BSChartCard`、`BSMetricTile`；体征从 4 张迷你图卡改为指标格（HRV、静息心率、呼吸率、血氧；没有手腕温度，因为数据层目前没有这个字段） |
  | `workoutsCard`、`todayNutritionCard` | 各缩成一行摘要；训练行不再展示心率分区条 |

  | `errorBanner`、`unauthorizedBanner` | 合并为 L0 上方唯一的一条 `BSStateView` |

## 2. 健身页

- L0：`BSBodyMap`（新增，包装 `MuscleMap`；`BodySeekDesign` 因此新增对 `MuscleMap` 的依赖，`Package.resolved` 不变）+ 体能 / 疲劳 / 状态差三个数。肌群排名和"让 AI 教练排课"保留在图旁。
- L1：`BSCoachNote`，内容读 `DailyBrief.pageNotes[workout]`（`WorkoutFeature` 新增 `dailyBrief` 状态，`AppFeature` 同步分发），没有简报时用原来的负荷与恢复摘要。
- L2：待复盘改用 `BSActionRow`；负荷曲线用新增的 `FitnessFatigueChart`（`BSChartCard` 统计头显示体能、疲劳、状态差，拖动选点时联动）。
- L3：手表训练档案（`BSSection` + 卡片）。
- 计算在 `BodySeekCore/FitnessFatigue.swift`：体能（CTL）= 42 天指数加权负荷均值，疲劳（ATL）= 7 天；每步 `值 += (当天负荷 − 值) / 窗口`，第一个有负荷的日子作为起点；没有数据的日子不当作零，保持前一天的值。当天负荷与原 ACWR 一致（有心率分区取 TRIMP，否则取负荷分）。7 项单元测试覆盖：常数负荷、手算权重、阶跃响应、休息后状态差为正、缺失日、开头缺失、乱序输入。
- 替换：`TrainingLoadDashboardCard`（ACWR 卡）和 `LoadRecoveryComboChart` 不再被任何页面调用，文件保留。
- `ZoneBar` 改成单色负荷色阶。
- 未做：L2② "进步（力量、有氧、体型）三张 `BSMetricTile`"依赖 e1RM 等健身进步模型，本轮明确不做，所以这一块没有出现。

## 3. 营养页

- L0：`BSIntakeRing`（热量环 + 碳水、蛋白质、脂肪三条进度条；目标来自当前生效的营养目标）。
- L1：`BSCoachNote`，读简报的营养页解读；`nutrition-coach-advice-card`、`nutrition-ask-coach-button` 标识保留。
- L2：记一餐（两个主按钮）、当天餐次（原餐次卡，含"完成当天记录"）、本周 / 本月热量（`BSChartCard` + 新增的 `IntakeBarChart`，点柱子切换日期）。
- L3：周月看板（周期切换 + 宏量矩阵）、能量平衡（`BSMetricTile`）、"微量营养素明细"二级页（`NutritionMicronutrientsView`，29 项）、营养目标。
- 删除：页面底部"营养库 / 导出记录"两个按钮（和左上角菜单重复）；"AI 解读"按钮（解读已来自简报）。

## 4. 趋势页

- 周期切换放在页面最顶部，控制整页。
- L0：**暂时用五项分数纵览（`BSMetricTile` × 5）代替 `BSVerdictGrid`**，因为周期走向模型还没有做（设计文档 §11 第 6 步的约定）。
- L1：`BSCoachNote`，读简报的趋势页解读。
- L2：五张 `BSChartCard`（每个指标一张，取代原来"单图 + 指标切换条"）。图表本身不再带自己的读数栏（`showsHeader: false`），拖动选点时由卡片的统计头显示日期和数值，松手后恢复。
- L3：实验室（`BSLabEntry` × 3）：明日预测、我的规律、个人对照实验，各自是二级页（`TrendsLabViews.swift`）；原有内容整体搬入，标识不变。
- 删除：`LoadRecoveryComboChart` 对照卡（被健身页的体能-疲劳图取代）、"AI 深度解读"刷新按钮、指标切换条。

## 5. Coach 页与指标详情页

- Coach：卡片统一为 `BSCard`，回执用 `BSReceipt`（第四轮）；按钮、间距、圆角、不透明度全部换成令牌；滚动动画换成 `BSMotion`。对话流本身没有套 `BSPage`（聊天页需要底部输入栏和反向滚动）。
- 指标详情（恢复、睡眠、负荷、压力、能量）：卡片换成 `BSCard`，数字全部换成令牌。图表内容没有重新设计，只是随共用图表一起更新。

## 编译与类型检查

- 全部按计划拆成子视图、`@ViewBuilder` 和计算属性；`BSActionRow`、`BSReceipt` 里三个修饰符分开写的做法保留。
- 唯一一次类型检查失败：`WorkoutView` 里一个带三元表达式和闭包的 `BSSection(...)` 调用（"failed to produce diagnostic"），拆成独立的计算属性后通过。
- `BodySeekKit` 是 `warningsAsErrors`，新代码没有留下未使用的变量。

## 未解决或有意留下的事项

- 门禁没有切换为阻断。建议在 CI 里对 `BodySeekFeatures/` 和 `BodySeekDesign/` 加 `--strict`。
- `SleepStageChart` 仍依赖 `SleepChartKit`（非交互模式用它画图）；dataviz 要求删除第二套实现，但需要同时删除 `BodySeekChartTests` 里的 `communitySamples` 测试和 `Package.swift` 依赖，本轮没做。
- `BevelTheme` 仍被图表和少数页面用来取品牌色、营养四态色；`BSColor` 还没有完全取代它。
- `TodayFeature` 里的 `proactiveInsights`、`showEvidenceBreakdown`，`NutritionFeature` / `TrendsFeature` 里的 `generateNutritionAdviceTapped`、`refreshAIInsightTapped` 等状态和动作页面已不再使用，没有删除。
- 营养页 L0 的目标值取自当前生效的营养目标；没有设置目标时环只显示读数、没有进度。
- 健身页"进步"三张指标格、趋势页 `BSVerdictGrid`、趋势图的"未来 2 小时估算段"（`EnergyAreaChart`）都依赖本轮不做的模型，没有实现。
