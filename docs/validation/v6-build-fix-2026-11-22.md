## 3. 编译错误与修复

### 3.1 第一次 iOS 构建失败（已修复）

第一次 `xcodebuild test` 以退出码 65 失败。唯一编译错误：

```
BodySeekKit/Sources/BodySeekDesign/Components/BSActionRow.swift:32:9:
error: the compiler is unable to type-check this expression in reasonable time;
try breaking up the expression into distinct sub-expressions
```

- **原因**：`BSOutcomeFeedback.body` 在 `#if os(iOS)` 分支里把三个 `.sensoryFeedback(...)` 串在一条修饰符链上。iOS 的 `SensoryFeedback` 重载集合比 macOS 大，三条带条件闭包的调用放在同一表达式里超出类型检查预算。macOS 包构建能通过，所以包测试没有暴露它。
- **修法**：保持行为不变，把三种触觉反馈拆成三个私有 `ViewModifier`（`BSDoneFeedback`、`BSFailedFeedback`、`BSUndoneFeedback`），每个 `body` 里只保留一条 `.sensoryFeedback` 调用；`BSOutcomeFeedback` 只负责组合。没有改公开 API、触发条件或反馈类型。
- **验证**：修复后 `swift test` 仍全绿；iOS 构建中 `BSActionRow.swift` 编译通过，整个 `BodySeekDesign` target 通过，最终 `TEST SUCCEEDED`。
- 第一次失败的完整日志：`/tmp/bs-xcodebuild.log`；成功日志：`/tmp/bs-xcodebuild-2.log`。

除这一处外，第一到三份报告列出的其他风险点均未实际报错，详见第 5 节。
