# BodySeek UI v4 融合规格

> 状态：Accepted（2026-11-23，作者与项目负责人确认）
> 设计依据：`design/prototypes/ui-v4-prototype.html`（作者提供的 v4 交互原型，网页版，canvas 手绘图表）
> 关系：本规格**优先于** `design-system.md` §5（页面规格）和 `dataviz.md` 中与之冲突的条款；令牌、组件、交互原则（design-system §2、§4、§7）继续有效。
> 本规格回应作者 2026-11-23 提出的 6 点意见：① 首页五项不全是环、建议收进弹窗；② 迷你图要有颜色；③ 顶部空白太多；④ 整体排版；⑤ Coach 未核实太多、表述防御；⑥ 趋势平时范围是固定长方形。

## 0. 三个已定决策

| 问题 | 决定 |
|---|---|
| 视觉基调 | **保持系统配色，只借 v4 的布局**。背景、卡片、文字用系统语义色（`BSColor`），领域色沿用现有五色。不引入 v4 的绿灰底色和深绿主卡。 |
| Coach 入口 | **保留现在的独立按钮**（iOS 26 底栏右侧圆形 `.search` 角色 Tab）。底栏仍是 今日 / 健身 / 营养 / 趋势 四个 Tab。 |
| 趋势页结构 | **合并**：上方一张大图卡，下方是彩色纵览列表；每行带领域色迷你线，点哪一行，大图就切换成哪项指标。 |

融合方式：把 v4 当设计稿，用 SwiftUI 重新实现。**不嵌入网页**。

## 1. 全局

### 1.1 一行式标题栏（回应 ③）
- 所有一级页面去掉系统大标题（不再用 `.navigationBarTitleDisplayMode(.large)`）。
- 标题栏只占一行，高度 ≤ 44pt：左侧是页面标题（`title2` 加粗）+ 同一行的灰色副标题（日期或摘要，例如"11月23日 周一"）；右侧是至多两个圆形图标按钮（按页面不同：打卡、记一餐、补录、实验室），以及头像（进入设置）。
- 实现建议：`BSPage` 改用 `.navigationBarTitleDisplayMode(.inline)` 并隐藏系统标题，用 `ToolbarItem(placement: .topBarLeading)` 放标题和副标题，`.topBarTrailing` 放按钮；或者不用导航栏，把一行式 `BSPageHeader` 作为滚动内容的第一行。二选一，以"首屏第一张卡距状态栏不超过 52pt"为验收标准。
- 不显示品牌栏和"示例数据"标签（v4 的网页顶栏不采用）。预览模式下可以在设置里看到数据来源。

### 1.2 颜色（回应 ②）
- **作废** dataviz v2 里"过程用灰色、只有结论用颜色"的规则。所有迷你图、纵览列表的迷你线、走向行的迷你线都用对应的领域色。
- 体征用 Apple 健康的同类配色：HRV 用恢复色，静息心率用心率红，呼吸率用青蓝，血氧用靛蓝。新增令牌 `BSColor.heart`、`BSColor.respiration`、`BSColor.oxygen`（浅色/深色各一套，过对比度门禁）。
- 图标底色：领域色 × `BSOpacity.faint` 的圆角方块，图标用领域色（v4 的 `metric-icon` 画法）。

### 1.3 估算的画法
- **AI 估算一律用 45° 斜纹**（领域色细线 + 透明间隔），已记录部分用实色。适用于营养热量条、宏量营养素条、热量柱。
- 被排除的时段（例如训练时段的压力）用中性灰块，并写明原因。
- 虚线只用于预测段，不再用于估算。

## 2. 今日（回应 ①④）

自上而下：

1. **恢复主卡**（L0）：系统 `surface` 卡片，左右两栏。
   - 左：恢复图标 + "恢复"；大数字（`heroNumber`，例如 72）+ 灰色"/ 100"；状态标签（"平时范围内"，领域色 soft 底）；一行灰色说明（例如"夜间 HRV 低于平时范围"）；"查看恢复详情 →"文字按钮。
   - 右：竖分隔线 + "近 7 天恢复"小标题 + 7 天恢复折线（恢复色，2pt，末端圆点，底部浅色面积）+ 起止日期刻度。
   - 不再用环。
2. **今日建议入口**（L1，回应 ①）：一行紧凑卡片，Coach 徽记 + "今日建议 · 生成时间" + 两行内截断的建议摘要 + 右侧"N 条行动"标签。**点开是 sheet**（`.presentationDetents([.medium, .large])`），内容：
   - 建议标题 + 一段话；
   - 行动框：每条行动一行，带"加入计划 / 撤销"按钮（走 AppAction，A/B 级直接执行并出回执）；
   - "查看依据"展开区：恢复、状态差、昨夜实睡等，每条写明日期；
   - 最近的变化（来自 `DailyBrief.changes`）；
   - 简报反馈（准 / 不准 / 没用）。
3. **四项指标**（2×2，`BSMetricTile` 扩展）：每格包含领域图标块 + 名称 + 箭头；大数字 + "分"；一行灰色说明；**一张专属迷你图**；底部起止刻度。
   - 睡眠：昨夜分期条（4 条泳道，睡眠色明度阶梯），刻度"入睡 / 醒来"；
   - 负荷：近 7 天日负荷柱，今天实色、前 6 天领域色 52% 不透明度，0 值画小圆点；
   - 压力：今日按小时的柱，训练屏蔽时段画中性灰块，未来时段不画；
   - 能量：今日电量曲线 + 浅色面积 + 末端圆点。
   - 点击格子进入现有的指标详情页（保留 zoom 转场和现有 accessibilityIdentifier）。
4. **关键体征**：列表卡（`List` 行样式或 `BSCard` 内 `LabeledContent`），每行左侧名称、右侧数值 + 一行灰色比较（"较均值 −5 ms"、"接近平时"）。缺测显示 `--` 和原因。
5. **今日记录**：两行跳转（今日训练：名称 · 时间 · 时长 · 待复盘/已复盘；饮食：已记录 N 餐 · kcal）。

右上角按钮：打卡（`square.and.pencil`）、头像。

## 3. 健身（回应 ④）

1. **肌群疲劳卡**：标题 + "模型估算"灰字；正面 / 背面分段控件；左侧 MuscleMap（`BSBodyMap`，保留真实人体图），右侧各肌群疲劳条（负荷色，按疲劳降序，显示"x / 100"或"约 1.5 天"）；卡底三栏：体能、疲劳、状态差（负值用负荷色）。
2. **今天练什么**：一行 Coach 解读入口（同今日建议入口样式），内容来自 `DailyBrief.pageNotes[.workout]`。
3. **最近训练**：名称、时间、时长、kcal；复盘文本或提示；"记录复盘 / 编辑复盘"按钮（现有一句话复盘流程）。
4. **表现记录**：列表行。VO2max、体重这两项数据已经同步，有数据就显示最新值和变化；深蹲 e1RM 暂无数据模型，本轮**不显示假数据**，显示"复盘里记下重量和次数后可估算"的空状态行。
5. **训练计划变更**：列出 Coach 或建议应用过的计划变更，每条带撤销（走 AppAction undo）。
6. **体能与疲劳图**：保留现有 `FitnessFatigueChart`，放在页面末尾。

右上角按钮：补录（`plus`）、头像。

## 4. 营养（回应 ④）

1. **今日热量卡**：大数字"≈1,040 kcal"（含估算时加"≈"）；一行灰字"已录入 950 kcal · AI 估算 90 kcal · 1 餐待补热量"；热量进度条（已录入实色 + 估算斜纹），下方"日目标 2,300 kcal"；"宏量营养素"三行（已录入 + 估算斜纹 / 目标）；图例（已录入 / AI 估算）。不再用环。
2. **记一餐**：标题栏右侧按钮 + 卡片下方两个大按钮（说一句记一餐 / 拍照），沿用现有 AI 记饮食流程。
3. **餐次列表**：每行图标 + 餐名 + 描述 + "含估算"标记 + 右侧 kcal（含估算加"≈"，缺热量写"待补热量"）。点开是餐次详情。
4. **饮食建议**：Coach 解读入口，内容来自 `DailyBrief.pageNotes[.nutrition]`。**有缺口就点名具体营养素和数量**；记录不全时只写一句"今天还有 N 餐没记"，不写"暂时无法判断"。
5. **营养素明细**入口行（29 项微量营养素二级页，保持现状）。
6. **本周热量**柱图（保留，估算部分改斜纹）。

## 5. 趋势（回应 ⑥ 和合并结构）

1. 标题栏副标题显示当前周期日期范围；右上角"实验室"按钮（进入预测、规律、N-of-1）。
2. 周期分段控件：7 天 / 30 天 / 6 个月 / 3 年（保留现有四档）。
3. **大图卡**（`BSChartCard` + `BSChartHeader`）：
   - 统计头：默认"指标名 · 日均"+ 大数字 + 单位 + "x / y 天有记录"；选中某天后变成"日期 · 指标名"+ 当天值 + "低于 / 处于 / 高于平时范围 a–b（n/28 晚）"；出现"清除选中"按钮。
   - 图：7 天 / 30 天用折线（≤7 个点时画数据点），负荷用柱；6 个月 / 3 年用现有胶囊图。缺测断开。
   - **平时范围逐日滚动**：每天取它之前 28 天有效观测的 P25–P75，有效观测 < 7 天则当天不画。用中性灰填充（`BSColor.surfaceInset` 或 `tertiarySystemFill`），曲线用领域色。胶囊图按每个桶的末日取滚动分位。
   - 交互：横向拖动选点（先判断方向，横向超过 8pt 且大于纵向才锁定，避免和滚动冲突），每跨一个点一次 `.selection` 触觉；轻点选点；松手保留。
   - 图例 + 一行灰字说明平时范围的算法。
   - 可展开"查看逐日数据"（`DisclosureGroup`，日期 / 值 / 平时范围三列）。
4. **彩色纵览列表**（切换器）：恢复、睡眠、负荷、压力、能量、夜间 HRV、实睡时长，每行：领域图标块 + 名称 + 领域色迷你线（负荷用迷你柱）+ 右侧周期均值和变化。当前选中行用领域色 soft 底并加 `.isSelected` 无障碍特征。点击行切换上方大图，并滚动到大图。

## 6. Coach（回应 ⑤）

### 6.1 数字核对
现状问题：`NumericProvenanceVerifier` 只认工具结果里**原样出现**的数字，Coach 自己算出的差值、均值、换算单位（432 分钟 → 7.2 小时 / 7 小时 12 分）全部被判为未核实，并在正文里逐个打标记。

修改：
1. **工具结果直接给派生值**：`get_weekly_recovery_evidence`、`get_metric_trend`、`get_today_context` 等在证据里预先算好常用派生量：窗口均值、与对照窗口的差值和百分比、分钟与"x 小时 y 分 / x.y 小时"两种换算、次数和天数计数。
2. **核对允许的等价形式**：
   - 显示精度内的四舍五入（整数、1 位小数）；
   - 时间单位换算（分钟 ↔ 小时 ↔ "x 小时 y 分"）；
   - 对工具中任意两个允许数字的差值的绝对值（只限同一指标、同一单位）；
   - 计数类词（次、天、晚、餐、组）不参与核对。
3. **展示方式**：正文不再逐个插入"未核实"标记。回复底部一行：全部核对通过时显示"文中数字都已和本机数据核对 · 查看依据"；有未核对数字时显示"有 N 个数字未能核对 · 查看"，点开列出。
4. 仍保留红线：分数不得由模型重算；缺失不得写成 0。

### 6.2 系统提示词改写
- 把现在 10 条"绝不 / 严格 / 必须"改写成简短、正面的写法，总长度减半。
- 回复结构固定为：**结论（1–2 句，直接回答）→ 原因（按影响大小排序，每条带数字和窗口）→ 建议（具体到今天或这周）**。
- 语气：用确定的语气陈述数据显示的事实，例如"主要是训练加量，其次是睡得晚"。**禁止**套话："可能""或许""仅供参考""建议咨询专业人士""数据有限，无法判断"。只有数据真的缺失时，用一句话说明缺了什么，放在原因列表的最后一条。
- 仍不做医疗诊断；出现明显异常（例如静息心率连续多日远高于平时、血氧低于 92%）时，直接建议就医，而不是泛泛提醒。

### 6.3 评测
`BodySeekAgentEvals` 新增两项指标并纳入门槛：
- `defensive_phrase_count`：上述套话出现次数，门槛 0；
- `unverified_rate`：未核对数字占比，门槛 ≤ 5%（用新增的含派生值、换算值的测试夹具）。

## 7. 视觉验收

- 每改完一个页面，由 Claude Code 在模拟器（iPhone 17 Pro，预览参数 `-velaPreviewDashboard -velaInitialTab <n>`）截取浅色和深色截图，保存到 `docs/validation/ui-v4/<页面>-<light|dark>.png`，供作者审阅。
- 对照 `design/prototypes/ui-v4-prototype.html` 的手机宽度（≤ 700px）布局，以及本规格。
- 设计门禁（`scripts/check_design_system.py`）保持 0 违例。
